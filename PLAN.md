## 1. What we are building

A web app that produces candle-by-candle **binary-options signals** (BUY/CALL, SELL/PUT, SKIP) for Quotex **OTC** and **Live** pairs, using
free/self-hosted tooling only, with automatic result verification and honest live accuracy stats. A trading journal (dashboard, trade history, CSV
import, analytics, P&L heatmap) comes in the last phase.

Screens taken from the screenshots:
- **Quotex Signal** (manual): signal stats (total, win accuracy, BUY/SELL/SKIP split, avg confidence) · "how this strategy works" panel ·
  pair picker (OTC / Live tabs + search) · timezone · analysis time (HH:MM, "Use Now") · "Generate High-Accuracy Signal" → direction, pair,
  confidence bar (50/65/80/95), raw score (+70/100, STRONG).
- **Quotex Signals** (published): admin-generated batches per hour ("20:00–21:00, 1m candles", 5W 2L, 7 signals), each signal with pair, confidence
  (e.g. 92%), result tag (MTG1 WIN), delete; tabs "Published Signals" / "Generate & Publish" (≥85% confidence, previous candle verified).
- **Journal** (later): Dashboard (equity curve, win-rate donut, recent trades, P&L heatmap), New Trade, Import CSV, Trade History, Analytics, Settings.

Existing strategy weights (keep as the baseline engine): Bollinger-band bounce 30% · RSI divergence 25% · Stochastic %K/%D cross 20% ·
CCI extreme + reversal 15% · Candlestick pattern 10%; trade only when ≥3 factors agree.

## 2. Reality check (read before building)

1. **OTC prices are synthetic.** Quotex OTC "pairs" are generated by the broker (weekend/off-hours instruments). No third-party provider sells that
   feed; the only source is Quotex's own platform stream. Live-market pairs track real FX/crypto/commodity prices closely but not tick-for-tick.
2. **Quotex has no official public API.** Community libraries ([cleitonleonel/pyquotex](https://github.com/cleitonleonel/pyquotex),
   [A11ksa/API-Quotex](https://github.com/A11ksa/API-Quotex)) reverse-engineer the private WebSocket. They break when Quotex changes things, may
   violate Quotex's ToS (account-ban risk) and history is limited (~199 candles per request).
3. **80–85% accuracy is not a realistic target for 1-minute binaries.** Break-even win rate is 1/(1+payout): ~54% at 85% payout, ~52% at 92%.
   Public indicators (BB/RSI/Stoch/CCI) on 1-minute candles are close to noise; OTC synthetic prices may behave differently again. We will build
   backtest + walk-forward validation and **show the measured live win-rate only**. Publishing a fixed "80–85%" claim to paying members
   without a verified track record is a consumer-protection risk.
4. **Regulation.** Binary options are banned/restricted for retail in the EU, UK, Australia and the US (offshore brokers get CFTC warnings); Quotex is
   reported as unlicensed by top-tier regulators. Status in India needs checking against SEBI notices. A paid signal service needs disclaimers and
   geo/legal review. (Sources are secondary; verify with regulators.)
5. **"MTG1"** in your screenshots = 1-step martingale. Martingale hides losses and inflates "win" counts; we will track **raw (no-martingale)
   results separately** from MTG results.

## 4. "AI" without subscriptions

Do **not** ask a chat LLM "will the next candle go up". Use a layered approach, all self-hosted:

1. **Rules engine** – the 5-factor confluence score above (pandas-ta / TA-Lib). Deterministic, explainable, backtestable.
2. **Calibrated ML classifier** – LightGBM/XGBoost on engineered features (indicator values, candle shapes, volatility regime, session/hour, multi-timeframe
   context, spread of factors). Label = next-candle(s) direction at expiry. Probability calibration (isotonic/Platt) so "84% confidence" actually means
   ~84% historically. Runs fine on CPU.
3. **Optional forecaster feature** – [Kronos](https://huggingface.co/klok123/Kronos-mini) (MIT, candlestick-native, mini 4M / small 25M / base 110M params) or Chronos-2 (Apache 2.0) as an extra feature, not as the decision-maker.
   TimesFM 2.5 is Apache 2.0, 3.0 is non-commercial. Benchmarks are zero-shot claims; we validate ourselves.
4. **Local LLM (Ollama: Qwen/Llama)** – only for writing the human-readable explanation ("BB lower-band touch + RSI bull divergence + Stoch cross"). Never for the prediction.
5. **Gating** – publish only when calibrated probability ≥ threshold AND ≥3 factors agree AND regime filter passes (no news spike, enough volatility,
   not mid-trend). Otherwise **SKIP**. SKIP is the main lever for quality.

## 5. System architecture

```
Quotex WS client ─┐
Binance WS ───────┼─> Ingestor (Python, asyncio) ─> Redis pub/sub ─> Candle builder (1m/5m) ─> TimescaleDB (Postgres)
History loaders ──┘                                                          │
                                                                             ▼
                                   Feature/indicator engine ─> Signal engine (rules + ML) ─> signals table
                                                                             │                       │
                                          Result verifier (settles at expiry, W/L/raw vs MTG) <──────┘
FastAPI (REST + WebSocket/SSE)  <── Postgres/Redis        Next.js frontend (dashboard UI)        Telegram bot (free delivery)
Ollama (explanations)   Backtester/research notebooks     Admin: generate & publish batches
```

- **Backend:** Python 3.12, FastAPI, asyncio workers, SQLAlchemy, Alembic.
- **DB:** PostgreSQL + TimescaleDB (candles, signals, results); Redis for live fan-out and job queue.
- **Frontend:** Next.js + Tailwind, dark purple theme matching screenshots; live updates over SSE/WebSocket.
- **Deploy:** Docker Compose on the VPS, Caddy/Nginx + HTTPS on your domain, GitHub Actions deploy. Suggested VPS: 4 vCPU / 8 GB RAM / 80 GB SSD
  (no GPU needed for LightGBM + Kronos-mini/small).
- **Auth:** email/password + roles (admin, VIP member) + subscription flag (can reuse existing LegendJournal auth if that stack is shared).

Key tables: `instruments`, `candles(instrument, tf, ts, o,h,l,c,v)`, `signals(instrument, candle_ts, direction, confidence, raw_score, factors json,
model_version, status)`, `signal_results(signal, entry_price, exit_price, outcome, mtg_step)`, `batches`, `users`, `subscriptions`, later `trades`.

## 7. Risks and mitigations

- Quotex protocol change / ban → isolate behind a `DataProvider` interface, dedicated account, kill switch, alerts when feed stalls.
- No real edge found → product pivots to risk-managed journal + education + transparent stats; never fabricate accuracy.
- Overfitting → walk-forward only, hold-out period, minimum sample size (≥300 signals) before showing a pair's win-rate.
- Timing/latency → signals generated for the *next* candle, computed from the last closed candle; target <2 s from candle close.
- Legal/ToS → disclaimers, no profit guarantees, geo-restrictions, legal review before charging members.
